実施日：2026-11-06

## 1. 結論

- **CLAUDE.md は機能している。** 新規セッション相当のエージェントに本ファイルのみを読ませたところ、スコープ逸脱を誘う 9 場面すべてで規則どおりの判断をした
- **既存コードは 5 原則に概ね準拠している。** ただし原則 3（コメントの保持）に不足を 1 件確認した
- **規則だけでは防げない事例もあった。** 未確認のまま仕様を決めた事例、テストの「赤」がコンパイルエラーのみだった事例がある

## 3. 検証結果

### 3.1 アーキテクチャ原則

| 原則 | 結果 | 根拠 |
|---|---|---|
| 1. プラグイン化 | 準拠 | Spring、JPA、Lombok の名前を判定に使うコードは `analysis.plugin.springboot` のみ。`analysis` 直下の該当箇所は Javadoc の例示と、ツール自身の `@Service` のみ |
| 2. IR による分離 | 準拠（生成層は未実装） | `ir` は JavaParser、Spring、他パッケージに依存しない。`generation` は `package-info.java` のみのため、実効的な確認は No.12 の実装後と No.13 の Hook で行う |
| 3. 情報の保持 | **一部不足** | Javadoc は型、フィールド、メソッドのいずれも保持する。一方、Javadoc 以外のコメントは型のみ保持し、フィールド、メソッドのコメントとメソッド本体内のコメントは保持していない |
| 4. 大規模対応 | 準拠 | IR をパッケージ単位で分割保存する。図の階層表示は `docs/screen-design.md` で定義済み |
| 5. データモデル優先 | 準拠 | JPA 関連を抽出済みで、未指定の名前は推測しない。実 OSS での確認は No.9 で実施済み |

その他の依存方向：`upload` は `analysis`、`web` に依存しない。`analysis` は `upload`、`web` に依存しない。両者の連携は `web` のみが担う。

## 4. 注意すべき運用上の事象

**セッション開始時に読み込まれた CLAUDE.md は、その後の編集を反映しない。**

本検証中に、ユーザーが追記した規則（範囲外の不具合、ブランチ運用など）が会話中の内容に反映されず、古い内容に基づいて提案した事例があった。ユーザーの指示で再読込して判明した。テストのエージェントにも同じ古い内容が渡されており、ディスク上のファイルを読むよう指示していたため正しく判断できた。

運用として、セッション中に CLAUDE.md を編集した場合は、再読込を指示するか新しいセッションを開始する。
